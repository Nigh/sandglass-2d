# 固定体积颗粒与性能回归

2026-10-29。修复上一版接触求解器造成的性能、压缩与沙堆滑塌问题。保留一万粒细砂、自动传感器和薄容器壁面摩擦。

## 上次变更的评估

上一版在桌面 CPU 上每个 120 Hz 物理步就需要约 11.6 ms，超过 8.3 ms 的预算，无法作为移动端通过标准。整体自由落体速度还会触发全体粒子的多重子步；密集颗粒需要的接触迭代又进一步增加开销。默认运行 20 秒后，检测到最坏约 18.2% 粒径的重叠，发生重叠的接触平均约 3.25%。原来的测试没有检查这些量。

仅在速度层处理摩擦，随后进行无摩擦的位置修正，也会让已经堆起的颗粒逐步滑动。[Unified Particle Physics 第 6.1 节](https://matthias-research.github.io/pages/publications/flex.pdf) 专门讨论了位置修正绕过静摩擦导致沙堆塌陷的问题。试验中，单纯取消子步、增加位置摩擦或改变有效质量，没有同时满足性能和堆积要求，未保留这些改法。

本次删除该刚体接触内核、预编译 WebAssembly 和 LLVM 构建步骤，改为适合电子沙漏的固定体积格点颗粒。它是视觉交互模型，不是完整离散元或论文求解器。

## 当前算法

- 格距为粒径 1.3，每格最多一粒。所有位置都来自格点；任意两粒中心距离至少一个粒径，数量与体积不会因压力而压缩。
- 每一步先预测活动颗粒的速度与位移预算，再处理占用依赖；本步搬移新唤醒的颗粒留到下一步预测，避免重复积分。目标被占用时，检查同方向整条链：能移动则整条链一起移位，并扣除每粒已经被推进的位移预算；悬空区域不会把运动中的邻居当作固定世界支撑。对于与重力前方玻璃连通的密集沙床，抑制沿重力直接挤整列的请求，改由侧向剪切和空位传播补砂，避免中心列独占出口。
- 颗粒的位移预算可以暂时为负，表示被前方传递的位移提前带动，随后等待自己的预算追上；它不会被误当作反向速度。
- 堵住后的颗粒沿超过休止角的方向松动；允许整条链侧向让位，优先选择接近休止角的方向，并打乱请求顺序，防止中央列抢占出口。方向阈值为 `along > 0.64 × cross`，对应约 32.6°，格点离散后实际约 33°。完全落定后跳过计算，输入改变后唤醒。
- 窄口宽 5.2，约四个粒径，恢复为细流；颈口使用局部阻尼和每粒 80 单位/秒的输运预算限制出砂速度，预算不足时保持等待状态，不会错误地把余砂休眠。
- 该模型没有需要高频迭代的弹性接触，固定物理步长改为 1/60 秒。Worker 单次最多追算 3 步、约 6 ms 的计算预算，单步超时会在该步后立即让出执行；不再把积欠的 12 步连续算完才发布状态。超慢设备仍可能慢放，但不会通过删砂或缩小体积追赶。

格点会量化微小运动、曲线和坡角；链式剪切近似密集沙的让位，不是严格的接触冲量或动量守恒模型。悬空同速沙团仍保留一致的自由落体速度；不能据此宣称实现了真实砂材的全部动力学。

## 回归检查

`npm test` 覆盖物理、传感器、Worker 调度及活动集的行为回归：

1. 细颈默认一万粒：8 秒时两侧均超过 75% 的近颈颗粒（活动集版本实测 78.2% / 82.8%）向内补位或穿过窄口；16 秒时两侧均超过 80%，防止中央形成独立运动通道。
2. 160 粒悬空沙团连续反向 12 次：速度与自由落体参考一致，质心在两格以内，整团相对位移差不超过一格，防止重新逐层落下。
3. 一团原本接触底部的砂带有向上初速度时整体离开支撑，速度仍与参考一致，防止摇晃惯性被支撑状态抹掉。
4. 2400 粒三个完整漏砂/翻转周期，加横向、强加速度与摇晃：每次都排空上腔、落定静止，并始终保持唯一格子所有权、有限坐标和容器边界。
5. 短加速度释放后保留空中惯性。
6. 平放壁面压力能停止运动并保持小倾斜，三轴零输入保留惯性，大倾斜后重新运动。
7. 默认一万粒在 10–150 秒期间每 10 秒检查流动/落定坡角，均在 30°–38°；落定后两侧均在 30°–37°，继续 30 秒位置完全不变，同时检查格点中心和格子唯一所有权，约束零重叠、固定体积。
8. 屏幕方向、极性、自由落体与输入限幅。
9. 法向压力、正反平放与三轴限幅。
10. 用确定性的每步 25 ms 假物理运行真实 Worker 调度器：一次只算一步，积欠不会形成长批次，持续发布新状态，暂停后不再推进。

## 性能与浏览器

完整原始结果：[600 秒模拟](benchmark.json)、[浏览器](browser-performance.json)。耗时来自 Intel Core Ultra 7 265K、Node.js 24.9.0；浏览器是桌面 Chrome 的手机视口，不能当作实体手机测量。

以下为活动集优化前的同机基准，保留作为历史记录；当前活动集的对照结果见文末：

| 指标 | 上一版接触模型 | 当前固定体积模型 |
| --- | ---: | ---: |
| 物理步频 | 120 Hz | 60 Hz |
| 活跃单步中位数 | 11.8 ms | 2.95 ms |
| 每模拟 1 秒的 CPU 时间 | 约 1425 ms | 约 177 ms |
| 最终两侧坡角 | 原测试未约束全过程 | 33.35° / 33.10° |
| 完全落定 | 仍有 18 粒留在上腔 | 108.6 秒，上腔排空 |
| 落定后 5 秒位移 | 0 | 0 |

生产构建的手机视口测试约 60 FPS 绘制、约 60 Hz 真实位置变化，墙钟 10 秒推进约 9.9 秒模拟。页面四倍 CPU 节流时绘制约 40 FPS；这不代表 Worker 或实体手机也受到了同样的节流。

当前每模拟秒的 CPU 开销约下降 88%。600 秒测试结束时仍有 10000 个独占格子，没有越界；全过程另由单元测试检查体积和坡角。改用 60 Hz 是因为该格点模型不需要依靠高频弹性接触迭代阻止压缩，并非减少沙粒或降低粒径。

浏览器记录分别给出 Canvas 绘制帧率、Worker 的真实新状态频率和模拟时间。页面的四倍 CPU 节流不保证同样影响 Worker，因此还用上面的确定性慢物理调度测试约束积欠行为。比较物理单步时不并行运行其他 CPU 密集测试。

`npm run test:browser` 覆盖手机自动传感器、手势授权、拒绝、读数过期、平放，以及手机/平板/桌面/横屏布局、暂停、翻转、颜色和沉浸。截图：[手机](mobile.png)、[桌面](desktop.png)。

## 手机输入

手机打开后自动尝试传感器；要求用户手势的浏览器会显示授权按钮，[平台说明](https://developer.mozilla.org/en-US/docs/Web/API/DeviceMotionEvent/requestPermission_static)。前后壁面静摩擦系数 0.45、滑动摩擦系数 0.35，由屏幕法向加速度估计压力；三轴零输入不伪造压力。读数过期或离开前台清除输入，后台暂停。

重力输入按平台统一符号：iOS/iPadOS 使用 +1，Android 及其他平台使用 -1；通过移动设备标识及触控 Mac 标识覆盖 iPad 桌面网站模式。手动方向开关仅反转自动适配结果，不改变壁面压力。回归检查覆盖平台识别、屏幕旋转、倒置、平放、零输入和手动反转。浏览器注入两种平台读数验证真实事件到 Worker 的重力输出；不代表实体 iPhone/Android 实测。仅靠加速度无法区分符号反转与手机倒置，因此不按启动姿势猜测方向。

尚未实体手机实测持续帧率、发热和摇晃手感。休止角是视觉标定值，任意倾角会受到格点方向离散的影响。

## 固定分块支撑实验

运行 `npm run benchmark:blocks`。活动集优化前的原始测量保存在 [block-benchmark.json](block-benchmark.json)，以下表格保留该阶段结果。实验只在内存副本中替换支撑传播，并标记颗粒搬移涉及的脏块；固定分块支撑尚未切换到生产算法。

先让默认 10000 粒砂自然落定，再分别挖去圆孔、横向贯通缝、竖槽、斜缝、微孔，另保留不挖空对照。块边长分别为 8、16、32 个格点。每个场景运行 120 步（2 秒），逐步比较原算法和分块算法的支撑标记、位置、速度、位移预算、占用、随机顺序及休眠状态，并检查剩余颗粒数量、格点所有权和容器边界。

分块内部保留多个独立连通分量，缓存分量的跨块边界连接及四向壁面接触。只重建脏块内部的连通关系，再从壁面重新计算分量图的可达性，避免失去壁面连接的环形砂团互相证明支撑。额外构造跨块单桥及环形结构，删除唯一支撑桥后，断言远端砂团失去支撑；同时检查重力反向、横向、零重力，以及完整床缓存后的局部删除。

计时排除逐步断言和参考求解器，交替运行原算法与分块算法三轮，取中位数。`wholeStepMs` 是包含休眠调用的完整 120 步平均；`activeStepMs` 只平均实际进行支撑计算的步；`supportMsPerCall` 是这些步中的支撑计算时间。另测完整床冷构建、缓存后挖空首查及几何不变时的重复查询。冷构建时间不包含索引对象的创建。

该阶段实验仍遍历整个分量图并写回全部颗粒的支撑标记，当时没有活动颗粒列表，也没有减少速度更新、随机排序、快照传输或 Canvas 绘制。桌面 CPU 耗时不能换算成实体手机耗电；几何不变查询的收益也不能冒充整场休眠的收益。

### 本机实验结果

在 Intel Core Ultra 7 265K、Node.js 24.9.0 上，原始沙堆在 108.6 秒模拟时间后休眠。6 个场景、3 种块尺寸共 2160 步逐步状态对照全部通过；跨块单桥、环形砂团失撑及输入方向变化检查也通过。

以下使用 16×16 格点块。运动粒数统计 2 秒内至少改变过一次格点的颗粒；单步耗时仅统计活跃步，包含支撑以外的原有全部物理工作。

| 挖空形状 | 移除粒数 | 初始失撑粒数 | 运动粒数 | 原算法活跃步 | 分块活跃步 | 耗时降低 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 圆孔 | 145 | 0 | 1675 | 2.978 ms | 2.799 ms | 6.0% |
| 横向贯通缝 | 444 | 3262 | 3262 | 1.760 ms | 1.731 ms | 1.7% |
| 竖槽 | 155 | 0 | 2213 | 3.046 ms | 2.844 ms | 6.6% |
| 斜缝 | 210 | 0 | 2539 | 2.951 ms | 2.743 ms | 7.0% |
| 微孔 | 5 | 0 | 151 | 2.784 ms | 2.593 ms | 6.9% |

圆孔、竖槽、斜缝、微孔的原始空格在 2 秒后全部填满；贯通横缝填充约 92.6%，上层 3262 粒整体失撑并移动。所有场景均重新休眠。初始失撑为零只说明仍有四邻域路径连至容器，不表示坡面和空洞边界不会滑动。

微孔删除后的首次重建只扫描一个块的 256 个格点；活跃步中的支撑计算从约 0.191 ms 降至 0.035 ms，但整个活跃步只减少约 6.9%。这说明块内缓存有效，单独替换支撑传播仍不足以大幅降低少量运动时的整体开销，后续需要活动颗粒及局部唤醒。

不挖空对照没有任何颗粒移动，重新唤醒后只计算 4 个活跃步。其活跃步中位耗时反而从约 1.488 ms 增至 1.842 ms，不能宣称所有场景都加速；短暂冷启动和少量样本不适合作为稳态性能结论。该实验没有证据证明 16 格是最优尺寸，也没有测量实体手机功耗，暂不切换生产算法。

## 活动颗粒更新

生产物理步改用紧凑的活动颗粒列表，只对活动颗粒积分和搜索移动方向。颗粒没有可用滑动路径、没有等待颈口预算且已受支撑时局部休眠；壁面静摩擦保持的零速度颗粒也可休眠。初始活动集合统一预测速度后再处理搬移，保留整团自由落体与离开支撑时的惯性。全局随机优先级仍按原算法洗牌，再筛选本步活动请求；不随活动数量改变随机数推进，也不在唤醒时重置全局排列，避免破坏颈口两侧的公平补砂。

唤醒依赖使用 16×16 格点块。失败的移动请求沿固定方向形成直线，因此每粒、每方向只缓存失败终端格，命中失败缓存时继续传递终端和颈口等待状态。休眠前沿这条离散射线按块跳跃登记依赖，不重新扫描整条占用链，也不混合不同方向的依赖。如果依赖块已在本步改变，直接登记一次整来源块唤醒，不构建马上会被清除的完整订阅。旧位置、新位置或支撑状态改变后，唤醒依赖这些块的来源块；采用保守的整块唤醒，避免遗漏远处空位引起的长链释放。

颈口预算按物理 tick 懒累积，休眠不会丢失等待期间的预算。失去支撑直接唤醒；输入变化仍保留原有的 2 单位阈值，跨越壁面启动阈值则独立唤醒，包括从零重力进入微弱非零外力。由于原积分器先计算阻尼再应用静摩擦，启动判断分别覆盖颈口与颈口外的阻尼阈值。本轮没有新增摩擦启停滞回，也没有改动运动加速度的模型。

运行 `npm run benchmark:activity -- --output docs/active-benchmark.json` 可测当前实现；加 `--baseline /path/to/physics.js` 可加载优化前的物理源码做同次运行对照。对照源码只在内存中重定位 geometry 导入，不作为另一套生产实现保留。原始测量见 [active-benchmark.json](active-benchmark.json)。

同机、同初始静床，三轮交替计时取中位数。每个场景观察 2 秒；下表统计整个窗口中全部活跃调用的 CPU 总时间，包含初次唤醒及后续再唤醒，不把休眠调用计入。全局随机数推进与洗牌规则保留，但局部休眠会改变请求集合，因此轨迹和重新休眠的步数不保证与旧算法逐位一致。

| 场景 | 优化前 CPU 总时间 | 活动集 CPU 总时间 | 加速比 |
| --- | ---: | ---: | ---: |
| 圆孔 | 79.50 ms | 43.70 ms | 1.82× |
| 横向贯通缝 | 13.19 ms | 15.82 ms | 0.83× |
| 竖槽 | 94.11 ms | 43.60 ms | 2.16× |
| 斜缝 | 75.95 ms | 41.02 ms | 1.85× |
| 微孔 | 39.64 ms | 20.78 ms | 1.91× |
| 单粒悬空、其余静止 | 199.52 ms | 31.71 ms | 6.29× |
| 2400 粒密集翻转与加速度脉冲 | 61.41 ms | 57.78 ms | 1.06× |

单粒悬空场景的活跃步均值从 2.978 ms 降至 0.473 ms；其中实际预测少于四分之一颗粒的步均值约 0.317 ms，最少只预测 1 粒。整个观察窗口的预测总数从 670000 降至 44761。微孔从 149925 降至 46055 次颗粒预测。圆孔、竖槽、斜缝及微孔仍全部填满；横缝仍填充约 92.6%，远端失撑区域下落。

并非所有场景都更快：不挖空但强制全量唤醒的四个活跃步，从合计 7.31 ms 增至 16.79 ms；横缝整体下落也有额外成本，密集脉冲控制组保持同一耗时量级。没有以更慢的试验中间实现作为比较基线。当前支撑传播仍为全量 BFS，失撑检查及公平竞争所需的全局随机优先级洗牌仍扫描全部颗粒；快照、绘制和输入变化引起的全量唤醒也未优化。本结果证明少量运动时的物理 CPU 开销下降，不代表实体手机功耗测量。

最终验证：16 项测试通过，包括远端断桥、自然移动终端释放长斜链、单粒惯性与静床不动、零重力后的微弱外力，以及跨越壁面静摩擦阈值的微小输入变化。近颈两侧 8 秒补砂比例为 78.2% / 82.8%，保留原有 75% 下限，没有降低回归要求。活动集与固定分块支撑组合再次完成 18 个组合、2160 步逐步状态对照，结果见 [block-active-benchmark.json](block-active-benchmark.json)。

生产构建通过；真实浏览器加载构建产物后，Worker 持续推进、砂穿过颈口，点击翻转后继续运动，未记录页面错误。浏览器画面验证不是实体手机发热或耗电测试。
